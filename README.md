# 直角戗角工作台 v0.2

输入一份参数配置，重新计算 90°、左右对称的角部木构造，并同时生成立脚飞椽的单列排料方案。几何沿用第 5 版取消支点额外抬高后的构造方向。非直角功能留待后续。

![界面展示](image\image.png)

B=400 的 r6 已由用户认可并完成独立视觉收尾，原结果保留。2026-10-26 新结果 [v02_boundary_layout_B400_20261026](outputs/workbench/case-b0257e3b87884f2a88137a283f3a38da/index.html) 已生成（410.5 秒、66 件）：边界出檐椽及普通飞椽单独保留，内部摔网椽从弧等分点放线，撤销“只强转首根飞椽”的补丁。此次 n=5、每侧4根立脚飞椽进入排料；连续卷戗板包含边界普通飞椽支承。模型由独立子代理看图，主代理不追加视觉复核。范围与视觉状态见 [几何整改与视觉验收](VISUAL_ACCEPTANCE.md)。

排料按已经确认的做法：长边竖直、尖角 A 共底线，先画竖线，再以 b、c、d 曲线的交点取得四角，最后连接直线切割边。c 由 d 平移得到的近似只报告误差，不反过来限制模型参数或改变三维构件。

## 打开工作台

双击本目录的 **`启动界面.cmd`**，或运行：

```powershell
.\start_ui.ps1
```

工作台在本机浏览器打开，默认地址为 `http://127.0.0.1:8765/`。模型、参数、立脚飞椽排料都在同一页；使用本地资源，不需要联网。

1. 从默认结果或“尺寸与分椽变化”示例开始，修改左侧参数。高级参数收在折叠组中；可导入和下载 JSON 配置。
2. 校验输入后点击“更新模型”。校验只检查输入条件，不等于已经建成有效实体。
3. 计算时可以查看实际阶段和用时，也可取消。页面刷新后仍能查看任务状态；生成失败时保留原来显示的成功结果。
4. 成功后，同页自动载入新模型。切到“立脚飞椽排料”查看板材、三步放样与尺寸；导出始终对应当前显示的结果。
5. 历史结果中的“查看此结果”同时切换模型并回填该结果的主要参数、高级参数及案例名，不启动计算。“载入参数到草稿”只改草稿。

修改参数后会提示尚未生成，避免把旧画面误认为新尺寸。已经生成且通过验证的同参数结果会复用；配置名称不同不强制重算，但会显示实际载入的结果名称。计算源码变更后，旧结果仍可浏览，但不能作为新源码的缓存命中。

**更新速度：**当前 B=400 边界分档修正版实测完整重建约 6 分 50 秒（410.5 秒），此前 r6 为 242.169 秒；构造与构件数已改变，不能将 r6 的4分钟作为当前承诺。实测与优化依据集中在 [生成速度说明](PERFORMANCE.md)。输入检查和已有结果载入通常较快；工作台提供异步精确更新，不在每次输入时自动启动整模。不同参数可能耗时更久，或因几何关系不能成立而失败；界面不提供虚假的完成百分比。

关闭网页不会取消后台生成，可重新打开工作台查看。启动脚本重复运行会复用本工作台服务；默认端口被其他程序占用时，可用 `start_ui.ps1 -Port 8766`。同一工作台只允许一个后台服务实例，防止多个服务同时写任务记录。这是随当前项目运行的阶段性产品，尚不是可脱离项目依赖独立分发的安装包。服务仅监听本机；版本范围是 90° 对称角部，非直角与全宽椽面扭转仍留待后续。

## 命令行使用

在此目录运行：

```powershell
.\run.ps1
```

修改或复制 `configs/default.json` 后，指定配置及独立输出目录：

```powershell
.\run.ps1 -Config configs/default.json -Output outputs/my_case
```

每次生成完打开输出目录的 `index.html`。`model.html` 是三维查看器，`layout.html` 是立脚飞椽排料页；均使用本地资源，不需要网络。

旧版默认结果入口为 [outputs/default/index.html](outputs/default/index.html)，其完整 CAD 重建约需 15 分半；仅重制页面和静态图约数秒。新旧版本耗时分别记录在 [生成速度说明](PERFORMANCE.md)。命令行与工作台共用同一个几何生成流程。

也可以直接运行 Python：

```powershell
$py = "$env:USERPROFILE/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe"
& $py generate.py --config configs/default.json --output outputs/my_case
```

程序使用本项目已经安装的 CadQuery/OCP、NumPy、SciPy 和 Matplotlib，依赖入口位于项目的 `资料整理/tmp/model_deps` 与 `资料整理/tmp/section_plot_deps`。这份生成器与项目一同使用；单独移动目录时还需带上或重新配置这些依赖。

## 输入与输出

有效输入、单位、默认值、派生关系和被替代的旧参数，见 [参数说明](参数说明.md)。配置中的未知参数应报错，避免用户以为一个没有接入几何的值已经生效。

| 生成文件 | 用途 |
| --- | --- |
| `index.html` | 本次生成结果入口 |
| `model.html`、`model_mesh.json`、`model.obj` | 三维查看器、分构件三角网、OBJ 模型 |
| `layout.html`、`layout.png`、`layout.svg` | 单列排料、三步放样和定位曲线 |
| `marking_points.csv` | 按竖线累计坐标排列的 A/B/C/D 尺寸 |
| `profiles.json` | 本次模型产生的立脚飞椽中心截面与梯形近似 |
| `layout.json` | 板材尺寸、角点、样条分段系数、曲线平移及误差 |
| `parameters_resolved.json` | 本次实际使用的输入和派生量 |
| `validation.json` | 生成记录；新结果记录视觉检查待完成，不等于构造验收通过 |
| `manifest.json`、`delivery.json` | 生成物清单与展示文件来源 |

左右两侧对称，排料输出一侧的全部类型，并明确标注 **制作两套**。单板图中的根数是单侧模板数；三维模型包含两侧立脚飞椽。正身飞椽属于三维模型，但不进入这份排料表。

三维构件数包含望板等部件，不能直接当作椽根数。历史 v0.2 曾将上层卷戗板分成大量窄片，该做法已被用户否定，当前改为每翼完整连续的板。

## 计算关系

1. 参数先确定桁、老嫩戗、里口、板面与分椽线，再由中心控制值建立覆盖全翼及椽间空档的连续飞椽母板。各椽的 A/B 纵向竖直面与共同边界相交，取得各自的里口与梢端位置；相邻母线之间采用直纹单元。飞椽与里口承口共用这些带域及母板底面，上层卷戗板跟随实际椽顶承托关系，建筑两翼继续镜像。尺寸改变后重新求几何关系，不使用旧网格整体缩放。
2. 排料从本次生成的立脚飞椽数据提取中心截面，按当前研究约定整理为梯形；本期不处理全宽扭面的展开问题。
3. 每根梯形作刚体变换，使 AD、BC 竖直，A 落在 y=0；横向依次靠紧。各竖线的横坐标为这些梯形横向宽度的累计和。
4. b、c 取每根右竖线上的 B、C；d 取左竖线上的 D。三条独立样条经过原角点。
5. 若计算平移复用，求形如 `c_hat(x)=d(x−dx)+dy` 的近似，允许样条端段延长，报告每根 C 点的竖向误差。误差大小不作为模型生成的通过条件。

这里的梯形近似是本次排料研究沿用的定义。拟合曲线只用于定位；单根切割轮廓始终由四个角点连接为直线边。

新生成的排料页可显示样条控制点和控制柄线，并展开坐标表。实心圆是曲线经过的 B/C/D 节点，菱形是分段三次贝塞尔内控制点，通常不在曲线上；两者不能混作同一种放样点。控制点直接从现有样条分段系数换算，不重新拟合或移动角点。历史输出保留原展示文件。

核心自动检查 12 项通过，包括无效配置、根数与尺寸变化，以及缺根时正常生成和恢复命令均以非零状态退出。命令、记录与失败案例说明见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

相比此前固定案例研究，板宽增加 0.020909 mm、板高减少 0.350429 mm、利用率增加 0.031024 个百分点，平移最大误差增加 0.026312 mm。当前仅量化这组小差异，尚未定位到唯一来源，不把它强行归因于某一项改动。

默认案例的实体、网格和排料已完整生成，随后在验证摘要字段读取处出错；修复后利用保留数据补齐验证与展示，未为此再次重算 CAD。`validation.json` 区分了实体构造时的有效性守卫与恢复后的数据检查。上述有效变化案例已完成修复后的完整流程。

保留的两个失败候选只用于诊断：`size_variant` 在最靠角飞椽的里口覆盖预检中失败；`size_variant_valid` 虽通过姿态预检，但其 68 mm 宽度组合在末根飞椽的实体融合中失败。它们不属于可用参数示例，名称中的 `valid` 是试算时的候选名称，不表示已通过。当前流程会对缺根、姿态失败或无效实体明确报错；已有不完整网格也不能通过恢复命令被改判为完整模型。

## 文件组织

- `启动界面.cmd`、`start_ui.ps1`：本地工作台启动入口。
- `workbench_server.py`、`workbench_backend.py`、`ui/`：后台任务服务和同页参数/模型/排料界面。
- `ui_state/`：本机运行记录与缓存来源登记；生成结果本身在 `outputs/`。
- `check_workbench.py`、`tests/test_workbench_backend.py`：真实 HTTP 集成检查与任务服务测试。
- [工作台接口与验收约定](WORKBENCH_CONTRACT.md)：服务、任务、缓存和界面行为。
- [v0.2 升级约定](UPGRADE_V02.md)、[生成速度说明](PERFORMANCE.md)：本次几何和交互范围、性能证据。
- `generate.py`：命令行生成入口。
- `engine/`：参数、几何、截面及排料计算。
- `configs/`：默认和变化案例配置；`seed_catalog.json` 保存历史种子的固定源指纹和文件哈希。
- `render_delivery.py`：把已算结果生成离线页面、静态图和尺寸 CSV。
- `viewer.*`、`layout.*`、`vendor/`：查看器源码、模板及本地显示依赖。
- `outputs/`：各次独立生成结果。
- `.gitignore`：忽略输出、运行状态及缓存，不删除本地文件；新机器从配置重新生成，种子只有原文件与登记哈希匹配时才可载入。

只重新制作自己独立命令行输出的显示文件时运行：

```powershell
& $py render_delivery.py outputs/my_case
```

若 CAD、网格和排料已经写出，但最后的验证摘要或展示步骤中断，可恢复收尾：

```powershell
& $py generate.py --config configs/default.json --output outputs/my_case --finalize-existing
```

这条命令不重新计算几何，只接受与已有输出完全匹配的案例、参数和构件身份，并检查网格哈希及排料编号。修改参数后必须正常生成新案例，不能用恢复命令把旧模型配成新参数。`--no-render` 可用于仅写计算数据；`--step` 可在正常生成时额外导出 STEP。

上述示例要求 my_case 原先也使用 configs/default.json 生成；自定义配置须换成原配置。工作台已登记结果和两份固定历史种子按文件哈希验证，不应原地重制；修改源码后从工作台提交新结果，保留原历史身份。

工作台另外保存网格导出前的实体检查点：位于该次输出的 `geometry_checkpoint/`。若导出失败，检查点保留；随后正常点击“更新模型”，只有规范化几何参数、进阶参数、重新计算的派生量及几何源码身份一致，且所有 BRep 文件哈希、单实体与体积复核通过，才会自动复用实体并重新生成网格、截面和排料。案例名可以变化，几何采样参数不能变化。结果写入新的独立目录；原检查点来源留在记录中。检查点记录完整源码身份用于追溯，显示或导出代码修复不必使已验证的几何失效。网格导出成功后清理本次输出内的检查点；后续收尾失败则使用上述 `--finalize-existing`。检查点恢复耗时和从零建模耗时分别记录。
